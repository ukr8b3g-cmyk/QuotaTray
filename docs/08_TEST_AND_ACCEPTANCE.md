# 08 テスト・受け入れ基準

## 1. 単体テスト

### WeeklyBucketSelector

- exact 10080分
- primary/secondary両方
- 複数limitId
- 週間枠なし
- null/未知フィールド
- durationの近似選択

### ResetClassifier

- 定期リセット
- 予定外候補
- 券使用候補
- 券失効
- プラン変更
- 枠ID変更
- 一時的異常値
- 長いオフライン期間
- 重複排除

### Settings

- 既定値
- 旧schema移行
- 破損JSON
- ポータブル／インストール保存先

### Localization

- 全言語で必須キーが揃う
- プレースホルダー数一致
- 文字化けなし

## 2. 統合テスト

偽App Serverプロセスを用意し、JSONLで次を再現：

- initialize成功／失敗
- account/read認証済み／未認証
- ブラウザログイン成功／キャンセル
- rateLimits/read正常
- updated通知
- null credits
- プロセス異常終了
- 破損JSON行
- timeout
- 401

実アカウント認証をCIテストへ入れない。

## 3. UI手動テスト

- 100/125/150/200% DPI
- 1画面／2画面／モニター取り外し
- タスクバー上下左右
- ダーク／ライト／システムを再起動なしで切替
- 各言語を再起動なしで切替
- 透明度60/100をスライダー操作中に反映
- 最前面
- 位置固定
- 位置記憶
- 端吸着
- 起動時トレイ／コンパクト／詳細

## 4. 配布テスト

クリーンなWindows 11 x64 VMで：

- Installerの新規インストール
- 上書き更新
- アンインストール
- データ保持／削除
- Portableをユーザーフォルダーから起動
- 書込不可フォルダーの動作
- Codex未導入時
- Codex導入済み・ログイン済み
- 未認証からブラウザログイン

## 5. メモリ・長時間

### 24時間必須

- 60秒poll
- パネル開閉を自動反復
- 詳細／コンパクト切替
- 通知イベント注入
- App Server再起動を複数回

合格：

- App本体Private Bytesが時間比例で増えない
- 24時間でウォームアップ後の増加が10MB未満を目標
- USER/GDI handlesが増え続けない
- CPU待機平均が実用上ほぼ0%
- ファイルサイズが設計上限内

### 72時間推奨

Release Candidateで実施。

## 6. セキュリティ確認

- バイナリとソースを検索し、`rateLimitResetCredit/consume` が存在しない
- Cookie/Password APIを呼んでいない
- 生トークンやauthUrlがログにない
- ローカルポートをlistenしていない
- Shell injection可能な実行方法を使っていない
- 設定にシークレットがない

## 7. 受け入れ基準

- トレイ表示からコンパクトを開くと、キャッシュ値が即表示され、更新中になる
- 取得成功後、週間残量・次回リセット・最終更新が更新される
- 詳細に券件数、期限、履歴が表示される
- 予定外リセット候補が二重登録されない
- 設定は再起動後に保持される
- 初期状態で透明度100、最前面OFF、位置固定OFF、位置記憶OFF、端吸着OFF
- インストーラー版とポータブル版が両方起動する
- READMEとPRIVACYが実装と一致する
